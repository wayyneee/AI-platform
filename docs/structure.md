# 資料夾架構規則

> 本文件是專案資料夾與檔案組織的唯一真相。架構有新規劃時，先修訂本文件，再調整實際資料夾。
> 目標：統一、乾淨的資料架構，任何東西都找得到該在哪裡。
> 本文件為**跨專案共用的通用規則**，不寫入任何單一專案的內容；專案特有的內容寫在該專案的 `docs/design.md`。

## 總覽

```
/
├── CLAUDE.md            協作規則
├── <專案設定檔>          package.json、.gitignore、.env.example 等
├── docs/                文件（唯一真相）
├── src/                 實作
└── public/              專案資源
```

## 根目錄

- 只放 `CLAUDE.md` 與**必要的專案設定檔**（工具規定要放在根目錄才讀得到的檔案，例如 `package.json`、`.gitignore`、`.env.example`）。
- 不放任何實作程式碼、文件或資源。

## docs/ — 文件

```
docs/
├── design.md            設計圖：專案概觀、模組、功能、模組如何運作與相互傳遞
├── interfaces.md        介面定義：各模組之間、前後端之間的介面串接
├── progress.md          進度表
├── structure.md         資料夾架構規則（本文件）
└── spec/
    ├── client/          前端的設計與規格（對應 src/client/）
    │   └── <頁面名>.md  單一頁面的規格：有哪些區塊、顯示什麼、使用哪些元件、串接哪些後端模組
    └── server/          後端的規格（對應 src/server/）
        └── <模組名>.md  單一後端模組的規格：做什麼、細節怎麼做、為什麼這麼做
```

規則：
- 所有文件都放在 `docs/` 內。
- 日後新增的文件也放在 `docs/` 內。
- 同性質的文件有多份時，在 `docs/` 內建立子資料夾集中存放（例如 `spec/`）。

## src/ — 實作

### 前後端分離

網頁版與桌面版都分為前端（顯示）與後端（功能邏輯）：

```
src/
├── shared/              共用介面與型別定義
├── client/              前端：以頁面區分
│   ├── components/      跨頁面共用的元件
│   └── <頁面名>/
│       └── <元件>       只在本頁面使用的元件
└── server/              後端：以功能模組區分
    └── <模組名>/
```

#### shared/ — 共用介面
- 存放模組之間、前後端之間共用的介面與型別定義。
- 內容依照 `docs/interfaces.md` 實作，兩者必須一致。
- 只放定義，不放任何邏輯。

#### client/ — 前端
- 前端主要負責連接後端、把內容呈現出來，不放業務邏輯。
- 先以**頁面**區分，再於頁面內切分**元件**。
- 只在單一頁面使用的元件，放在該頁面資料夾內；跨頁面共用的元件，放在 `components/`。
- 如非必要，不切得太細。
- 每個頁面對應 `docs/spec/client/<頁面名>.md`。

#### server/ — 後端
- 後端負責邏輯與功能實作，以**功能模組**區分。
- 一個模組 = 一個資料夾，對應 `docs/spec/server/<模組名>.md`。
- 每個模組只負責自己的功能，透過介面接收與傳遞資料。
- 目的：物件導向、模組化、各自獨立。出問題時，錯誤可以鎖定在單一模組內，不會牽動整個專案。
- 模組如何切割，於 `docs/design.md` 中規劃。

#### 後端模組內部統一格式

```
src/server/<模組名>/
├── index            對外介面：其他模組只能透過這裡呼叫本模組
├── <內部實作檔案>    模組內部邏輯，外部不可直接引用
└── tests/           本模組的測試檔
```

（副檔名依各專案 `docs/design.md` 的技術選型而定）

### 桌面版說明

- 桌面版同樣分為 `client/`（顯示）與 `server/`（功能邏輯）。
- 桌面版的 `server/` 指的是「後端邏輯層」，不一定是獨立運行的網路伺服器；前後端如何溝通，由各專案定義於 `docs/design.md`。
- 若某專案確實不適合分前後端，須在 `docs/design.md` 中說明理由，經 PM 確認。

## 測試

- 測試檔放在各模組資料夾內的 `tests/`。
- PM 平時也會手動測試。

## public/ — 專案資源

- 專案需要用到的資源（圖片、字型、圖示等）都放在 `public/`。

## 修訂

- 之後如有其他規劃，討論後修訂本文件。
